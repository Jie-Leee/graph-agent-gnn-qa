# A 收尾结果、交接状态与后续职责

本次针对已发布模板v4、种子42的固定版本，补齐题面初审、风险处理约定和A侧
可执行接口验收。2500条QA、1250个查询组及原数据清单保持不变。这里的“收尾”
是完成A可以自行交付的材料，不代替B/D成员实际接入确认。

## 题面初审与全量标记

先对全部1250个查询组生成质量标记，再按确定性哈希抽样：每种关系路径最多
两组，并优先来自不同划分。实际选中77个独立组，覆盖全部39种路径，其中38种
各两组、1种仅有一组可选；训练42组、验证9组、测试26组。

77组均已逐条读取题面、全部答案名称和证据并记录模型语义初审：13组未发现明显
问题，58组需要按已披露边界解释，6组需要重点澄清。结论、理由和建议逐条保存在
[semantic_review.jsonl](../data/quality/semantic_review.jsonl)。这不是人工专家标注、
现实事实核验或同题双审；分层抽样结果不估计全数据错误率。

| 全量质量信号 | 查询组数 | 解释 |
|---|---:|---|
| 主题名在完整名称映射表中同名多ID | 63 | 属于候选歧义风险，非63道已确认错题 |
| 主题名在可见训练图中同名多ID | 61 | B做实体定位时更直接相关 |
| 同组答案中不同ID同名 | 1 | 两个Salzburg ID不能按字符串合并 |
| 题目相关名称带-GB/-US源后缀 | 315 | 统计主题、答案或证据节点；保留原名及ID |
| 至少一答案也为主题的一跳出邻居 | 128 | 拓扑重叠，不证明另一条边在语义上回答题目 |
| 所有答案也为主题的一跳出邻居 | 79 | 是上述128组的子集，不能重复相加 |

另提供答案规模1/2–5/6–20的分层，以及主题出度0–20/21–100/101+的分层，供E
事后分析。质量信号只作风险提示，不自动删题，不进入测试检索或Agent输入。

六个重点样本及处理决策：

| 样本 | 风险 | 当前固定版本处理 |
|---|---|---|
| `train-00470` | Election同名，contains返回大学 | 已知主题按ID保留；文本定位需消歧，不能解释为城市列表 |
| `test-00176` | Munich同名，Manhattan/New York City粒度不同 | 保留各ID并标记直邻重叠，不按地理包含合并 |
| `test-00066` | Brazil同名，职业标签有源后缀 | 主实验给定主题ID；展示别名不改变身份或金标 |
| `train-00400` | Madrid的contains答案含Real Madrid C.F. | 明示源关系尾实体可超出通常地点语义，保留语义风险；不能宣称题面已无问题 |
| `validation-00110` | artist包括乐队，nationality写成citizenship | 仅按源图关系近似解释，不作法律公民身份断言；语言升级另发版本 |
| `test-00158` | 两个Salzburg ID、地点类型混合、nationality近似 | 保留不同ID及完整集合，评测以ID为准，不称已消除歧义 |

这些记录是已明确标记和给出使用边界，不代表所有自然语言缺陷都已修复。
本版适合已知主题、固定训练图上的模板QA基线。若目标升级为无需给定主题的
自然语言QA，需要统一修订题面和消歧方式，发布新版本并对所有方案重新评测。
处理规则详见 [A数据质量处理约定](A数据质量处理约定.md)。

验证记录：原有12项检查与70项unittest合计82项通过；全部固定QA文件哈希保持
一致；三个自动质量产物在两个独立目录逐字节一致；77条语义记录与抽样ID一一
对应并覆盖39种路径。这些程序检查不替代语义审阅，也不构成人工验收通过率。

## 可执行交接结果

命令：`python scripts/accept_data_handoff.py`。
真实结果保存在 [handoff_acceptance.json](../data/quality/handoff_acceptance.json)。

| 检查 | 结果与范围 |
|---|---|
| A数据导出及哈希 | 通过；完整QA可读，推理文件与金标题面对应 |
| C训练/E金标读取 | 现有QAExample接口可读取2000/200/300条记录 |
| B现有框架 | 仅索引272115条训练边，38001条留出专属边未进入索引，300题均能运行 |
| B候选诊断 | 默认两跳/200节点/800边，平均答案节点召回44.4389%，不是QA准确率 |
| D问题输入契约 | 300个Question仅有编号、文本、主题ID；替换金标值后输入不变 |
| D实际Agent | 当前分支AgentRunner仍抛NotImplementedError，正式调用待D实现 |
| B/D等成员接收确认 | 尚未收到确认，不能用A侧检查替代成员签收 |

“不泄漏金标”指标准答案、预给标准路径和标准证据不被转交给测试推理；B自行
从可见图检索得到的真实证据可以进入text/gnn模式。本次未调用LLM，也未把记录型
输入探针当作实际D Agent实验。

B/D接入时应在组长安排的整合版本中运行以上检查。B优化后的实现可采用不同
索引结构，当前脚本主要验收既有GraphIndex框架；最终还需B自证同等可见图边界。
D完成实现后需检查自己的真实提示词和工具日志，不能仅凭本输入探针认定无泄漏。

## 为什么B和D都需要A

| 使用方 | 从A获取什么 | 后续负责人 |
|---|---|---|
| B检索 | 训练图、名称映射、固定问题及主题格式 | B建索引、做实体定位、优化候选与证据召回 |
| D Agent | 相同的问题集、Question输入协议、测试金标隔离规则 | D接LLM、决定是否调用B工具，并组织回答 |
| C GNN | 训练QA监督和固定验证/测试划分 | C训练与候选打分，另依赖B产生子图 |
| E评测 | 固定金标、版本哈希和质量分层 | E运行正式实验、分层指标、图表和整合 |

D的纯LLM模式可以先读取A题面开发；text模式依赖B检索，gnn模式再依赖C。
数据冻结后，这些模块读取同一份文件和稳定接口，不需要A每次在场重新处理。

## A后续还做什么

本次可自行完成的收尾材料已经交付；剩余外部环节是B/D成员接入后确认，不能
在他们模块未实现时由A代替完成。确认通过且没有新数据缺陷后，A主开发阶段结束。

A后续负责：解释数据协议；修复已证实的数据问题并记录版本；必要时为E解释
数据侧失败案例；准备并讲清自己的任务与数据汇报。A不需要负责B的召回优化、
C的训练、D的Agent开发或E的全部实验，也不需要为了持续有事做而不断加题。

数据版本只有在确有缺陷、接口确需变化或全组决定扩范围时更新。更新前说明影响，
所有方案用同一版本。若老师对数据来源或自然语言真实性提出新要求，那属于需
统一调整的项目范围，不能让A悄悄改完测试集、其他人仍使用旧版本。
