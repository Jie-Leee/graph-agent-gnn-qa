# A 数据：三页汇报提纲与讲稿

负责人 beihaigit233；约 5 分钟。以下内容可直接整理到组内统一 PPT 模板。

## 第 1 页：任务与真实数据来源（约 1 分 20 秒）

页面要点：

- 任务：在已知知识图谱上回答两跳问题，比较纯 LLM、图谱检索、图谱检索加 GNN。
- 来源：Microsoft FB15k-237；KG-BERT 实体/关系名称映射锁定固定提交。
- 可见图：272115 条训练边、14505 个实体、237 种关系；名称覆盖率 100%。
- 原始 valid/test 图谱边不进入出题过程。

讲稿：我们先统一数据入口，让检索、GNN、Agent 用同一张图和同一组题。
FB15k-237 原始数据是三元组，不是现成的自然语言两跳问答，所以我们明确采用
自构模板 QA。训练图包含约 27.2 万条边，名称映射覆盖全部训练图实体和关系。
我们保留关系类型与方向，只用训练三元组构成可见图。原始图谱的验证测试划分
仍保留用于统计，但不把其中新增边当作问答答案来源。

## 第 2 页：完整答案与分组划分（约 1 分 50 秒）

页面要点：

- 24 个语义明确的白名单关系，构造正向两跳完整答案集合。
- 按“主题实体＋关系序列”分组，组内两种问法不能跨划分。
- train / validation / test = 2000 / 200 / 300 条，共 1250 个查询组。
- 题面统一要求全部答案，不依据标准答案数量改变措辞。

讲稿：出题时，先固定主题和两步关系，再枚举所有中间节点，把全部可达终点
作为答案，不是只选一条路径。包含自环或回到主题的查询整组排除，答案太多的
查询也整组排除，避免删掉部分答案后仍声称答案完整。我们限制关系词表并手写
关系表述，避免直接拼 Freebase 路径产生难懂的问题。同一组生成两种问法，划分
单位是整个查询组，保证同一查询的改写不会同时进入训练和测试。当前规模是
2000 条训练、200 条验证、300 条测试。实体和证据边可以共享，因此这是已知图
上的查询泛化，不是未知实体或未知边的测试。

## 第 3 页：质量检查与下游交接（约 1 分 50 秒）

页面要点：

- 独立全图遍历检查完整答案；标准证据真实且两跳连通；重复与跨划分组为零。
- 推理输入与金标分开；固定种子、原始数据和输出 SHA256 支持复现。
- B 读取训练图，C 读取训练监督，D 读取 Question，E 单独读取测试金标。
- 当前简单 BFS 的答案节点召回约 44.44%，限额检索仍需 B 改进。

讲稿：数据入口的重点是能复现、能核验。我补上了完整图遍历检查，确保每道题
的标准答案与两跳可达集合完全相等，所有证据边都来自训练图。同组问法没有跨
划分，问句和问题 ID 没有重复。推理文件只保留问题、编号和主题 ID，答案、
标准关系路径与证据只用于监督或评测。这里提供主题 ID 属于已知主题设置，若要
测实体定位，需由 B 从题面重新预测。下载、构造、校验都有可运行脚本和文件
哈希。最后，全图中答案可达不意味着小子图一定召回；当前简单 BFS 在默认预算
下平均答案节点召回约 44.44%，这只是候选诊断。后续 B 改进检索、C 训练模型、
D 接入 Agent，再由 E 在统一数据与预算下评测。
