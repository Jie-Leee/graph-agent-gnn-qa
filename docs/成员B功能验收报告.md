**需要修正的正确性问题**

1. **缺失标注可能被报告为 100% 召回。**

   位置：`src/graph_agent/retrieval/benchmark.py` 第 23–24、69–70、82–88 行；`scripts/evaluate_retrieval.py` 第 16–18、40–41 行。

   `_recall()` 把空标准集合计为 1.0，CLI 又把缺失或 null 的答案字段转为空集合；可选证据字段缺失时也变为空集合。因此没有标注的数据会被当成成功检索：

   | 输入 | 实际输出 | 问题 |
   |---|---|---|
   | 一题没有答案/证据标注，图为空 | 答案和证据的宏/微召回全部为 1.0 | 没有评估依据，却显示满分。 |
   | 一题有证据但完全未召回，另一题无证据标注 | 证据宏召回为 0.5 | 唯一有标注样本的召回实际为 0。 |
   | 空 QA 数据集 | questions=0，宏召回=0，微召回=1 | 输出具有误导性且口径不一致。 |

   建议区分“未标注”与“明确标注为空”；对必需的答案字段做校验；答案/证据分别统计有效样本数；无可评估样本时显示未评估或明确报错。修正前不能直接用这些数字汇报检索质量。

2. **未在问题中出现的实体别名会误删关系词。**

   位置：`src/graph_agent/retrieval/graph.py` 第 193–198 行。

   当前从问题中删除主题实体所有别名的词，而非只删除实际命中的名称。最小复现：图中依次有 `film --cast--> actor`、`film --director--> director`；问题是 `Who directed Test Film?`，节点上限为 2。实体只有别名 `Test Film` 时返回 director；添加未提及的别名 `The Director's Cut` 后，关系词 `direct` 被删除，结果变成 actor。

   建议按实际匹配的文本范围移除实体名称，再计算关系相关性；添加同名词也用于表达关系的回归样例。

**两跳召回与效率的策略局限**

位置：`src/graph_agent/retrieval/graph.py` 第 220–241 行。

合成图中存在 `film → director → city`，另有 film 指向 200 位 actor。即使 director 关系优先级最高，默认 `max_hops=2, max_nodes=200, max_edges=800` 仍先装满一跳邻居，返回 200 节点、199 边，包含 director，却没有 city；节点截断标志为 True。将节点上限改为 203 后 city 出现。

这符合当前 BFS 的执行方式，但说明两跳答案会受到一跳预算分配的系统性影响。不能仅凭“支持 max_hops=2”判断两跳任务已经满足。建议比较每节点扩展配额、按相关性保留路径或分层预算策略，在验证集上选择参数，再固定配置测测试集；不能根据标准答案临时补入节点。

此外，每次扩展都会先对整个邻接表评分、排序，再执行规模截断。固定默认输出 200 节点、199 边，合成星形图的主题度数为 1,000 / 10,000 / 100,000 时，实际关系评分次数分别为 1,199 / 10,199 / 100,199；即便 `max_edges=1`，也先扫描全部主题邻接边。因此应在真实高出度样本上测 P95，不能把输出规模上限表述为计算量上限。
