# 五人 GitHub 协作指南

## 分支与权限

main 保存整合结果，另有五个个人工作分支，所以一共六个分支。

| 成员 | 工作分支 |
|---|---|
| A 数据 | codex/data |
| B 检索 | codex/retrieval |
| C GNN | codex/gnn |
| D Agent | codex/agent |
| E 组长及实验评测 | codex/evaluation |

每人主要修改自己负责的目录。公共接口和配置修改先沟通。分支不是权限隔离：有写权限的协作者通常能推多个分支，需遵守约定；可用时由组长另行设置分支规则。

## 加入仓库

私有个人仓库一般需要组长按 GitHub 用户名或邮箱邀请协作者，对方接受后才能访问和推送。普通仓库 URL 不等于自助申请加入链接。先把 GitHub 用户名发给组长，再接受通知或邮件里的邀请。

## 第一次操作

分支名换成自己的工作分支。以下以 A 的数据分支为例：

```bash
git clone https://github.com/Jie-Leee/graph-agent-gnn-qa.git
cd graph-agent-gnn-qa
git switch --track origin/codex/data
```

本地已存在该分支时直接 git switch codex/data。各人使用自己的账号认证，不共享密钥和密码。

## 每次开始开发

先提交或暂存未完成改动，再同步远程：

```bash
git switch codex/data
git pull --ff-only
git fetch origin
git merge origin/main
```

有冲突时核对双方修改后处理，不确定的公共接口请找组长一起确认。不要强制推送覆盖历史。

## 做完就发到自己的 branch

```bash
git status
git add src/graph_agent/data
git commit -m "feat: prepare grouped QA splits"
git push origin codex/data
```

上述路径是 A 的例子。各自做好了就发到自己的 branch，带上运行说明，群里说一声，不用等其他人一起提交。组长用 Pull Request 检查和合并：base 选 main，compare 选对应工作分支；改动、运行方法和对接需求写清楚。main 由组长统一合并。

组长阅读 PR、检查接口与敏感文件，必要时拉取分支联调，合并到 main 后通知大家同步。五个长期工作分支合并后先保留。能否强制要求 PR、阻止直接推送取决于账户方案和仓库设置，不能把口头约定当成已生效的保护规则。

## 仓库与邀请入口

仓库：https://github.com/Jie-Leee/graph-agent-gnn-qa

组长邀请入口：https://github.com/Jie-Leee/graph-agent-gnn-qa/settings/access

组长收集另外四人的 GitHub 用户名，在 Settings → Collaborators → Add people 中逐个邀请，对方接受后再克隆。该设置页是组长使用的管理入口，不是成员自助申请链接。main 及五个工作分支由初始化操作建立，后续按上面的 PR 流程协作。

## 完成时间

期限一周，周五之前完成。大家按自己的节奏做，做好就发到自己的 branch，群里说一声；需要对接的数据和接口提前沟通。组长负责评测代码、三组对比实验、消融结果汇总、图表和失败分析，最后把各模块联调并合并。

## 可直接发群里的说明

> 咱们就按这个分工来：A 负责数据处理和问答样本，B 负责图谱检索，C 负责 GNN，D 负责 Agent 和演示。我负责评测代码、三组对比和消融结果汇总、图表分析，最后把大家的代码整合起来。时间就一周，周五之前搞完就行，不按天卡进度。谁做好了就发到自己的 branch 里，群里说一声，顺带写一下怎么跑；有接口要对接就提前沟通。每人准备 3 页左右 PPT，讲 5 分钟左右。
