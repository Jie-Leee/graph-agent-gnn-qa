**评测结果应怎样理解**

- `answer_evaluated_questions`、`evidence_evaluated_questions` 分别表示参与答案/证据召回计算的有效题数；对应 `*_skipped_questions` 表示跳过的题数。
- Python 评估接口将缺失或空金标集合排除在该项召回的分母之外，但仍统计查询耗时。没有有效金标时，宏/微召回均为 `None`，写入 JSON 后是 `null`。它不评估“明确无答案问题”的作答能力。
- 命令行评估要求 `answer_ids` 是非空字符串列表。缺失、null、空列表或空字符串都会报错，因此不能误用 `*.questions.jsonl` 进行召回评估。
- `evidence` 可缺失、为 null 或为空；这些样本不参与证据召回，仍可参与答案召回。错误的三元组格式会报错。
- 输入校验失败时不创建或覆盖报告；有效输入的输出父目录会自动创建。

**检索行为与接口**

`Question → GraphIndex → Subgraph` 的调用方式保持兼容，默认仍为两跳、最多 200 个节点、800 条边，并允许反向遍历。检索器只接收问题和主题实体 ID；标准答案和标准证据只在查询结束后参与评估。

分层预留解决了一跳先占满预算的问题；纯星形图没有第二跳可查时，可以把剩余额度用于更多一跳节点。多主题会轮流扩展，避免总由第一个主题先占满小预算。节点满额后仍可保留已选节点之间的边。

更短路径稍后出现时会更新深度并重新扩展。最终在已选三元组上重新生成最短路径，确保路径连续、属于返回子图，原始关系方向和反向遍历标记一致。跳数、节点数和边数上限仍是硬限制；暂时预留不直接算作截断，实际因上限丢弃时才记录。

**真实数据对比**

两版使用同一份 A 的固定 QA、同一评测口径、训练图及实体/关系名称映射。问题提供主题 ID，所以这组结果衡量已知主题的图谱检索；自动实体定位需另行评估。只在验证集选择算法方案，随后固定实现，再评估测试集。

旧版为提交 `7f53e06` 的检索器；两版参数均为 `max_hops=2, max_nodes=200, max_edges=800, allow_inverse=True`。全部 200 道验证题和 300 道测试题的答案与证据标注均有效，跳过数为 0。

| 数据 | 指标 | 修复前 | 修复后 |
|---|---|---:|---:|
| 验证集（200题） | 答案节点宏召回 | 47.68% | 71.14% |
| 验证集（200题） | 答案节点微召回 | 48.10% | 61.25% |
| 验证集（200题） | 证据三元组宏召回 | 69.41% | 81.36% |
| 验证集（200题） | 证据三元组微召回 | 65.88% | 74.55% |
| 测试集（300题） | 答案节点宏召回 | 43.74% | 59.51% |
| 测试集（300题） | 答案节点微召回 | 35.14% | 49.08% |
| 测试集（300题） | 证据三元组宏召回 | 65.41% | 73.42% |
| 测试集（300题） | 证据三元组微召回 | 57.39% | 66.67% |

宏召回先逐题计算再取平均，微召回按全部标准答案或证据的总数计算。这些是候选节点和证据的覆盖率，最终问答准确率还需要 Agent/GNN 接入后另行评测。

| 数据 | 平均耗时 ms：前 → 后 | P95 耗时 ms：前 → 后 |
|---|---:|---:|
| 验证集（200题） | 55.70 → 45.12 | 104.83 → 170.03 |
| 测试集（300题） | 59.10 → 49.39 | 97.92 → 185.33 |

平均耗时有所下降，但 P95 上升，说明少数高开销查询仍存在效率取舍。当前算法会扫描被扩展节点的邻接边；输出规模有上限不等于扫描量也有相同上限。这是本机 Python 3.11.9 的单轮结果，计时包含实体处理和检索，不含图谱加载、建索引和格式化；不能据此承诺稳定的线上延迟。
